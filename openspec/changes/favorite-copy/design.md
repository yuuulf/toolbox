# Design

## Context

- お気に入りの各色は `<li>` の中に「色見本 + HEX のボタン（押すと変換欄に読み込む）」と、境界線で区切った削除ボタン（`IconButton` の `variant="subtle"`、`p-1`・枠なし）を並べている（`components/tools/color-tool/favorite-colors.tsx`）
- `CopyButton`（`components/copy-button.tsx`）は枠あり・`p-2` の見た目だけを持つ。結果はアイコンの切り替え（チェック／×）と `aria-live` の読み上げで伝え、約2秒で戻る
- AGENTS.md は「コピーは必ず `CopyButton` を使う」「追加・削除は `IconButton`」と決めている

## Goals / Non-Goals

**Goals:**

- コピーの動き（書き込み・結果の伝え方・空のとき押せない）は `CopyButton` のものをそのまま使い、お気に入り用に作り直さない
- 一覧の1項目の見た目を、削除ボタンと並んで1つのまとまりに見える大きさに保つ

**Non-Goals:**

- `CopyButton` と `IconButton` の統合

## Decisions

### D1. `CopyButton` に `variant` を追加する

`variant?: 'default' | 'subtle'` を追加する。`default` は今の枠あり・`p-2`（既存の呼び出しは変更不要）。`subtle` は `IconButton` の subtle と同じ `rounded p-1 text-zinc-500 hover:bg-zinc-100 hover:text-zinc-900`（ダークも同じ対応）で、枠を付けない。成功・失敗の色（緑・赤）は `subtle` でも付ける（`text-zinc-500` より後に効くよう、状態の色があるときは `text-zinc-500` を付けない）。

- 代替: お気に入りでは既定の枠ありの `CopyButton` をそのまま置く → 枠と `p-2` で項目の高さが増え、隣の削除ボタン（枠なし）と見た目がそろわない
- 代替: `IconButton` に `CopyIcon` を渡してコピー処理を書く → コピーの結果の伝え方を二重に実装することになり、AGENTS.md の「コピーは必ず `CopyButton`」にも反する

### D2. 項目の並びは「色見本のボタン | コピー 削除」

`<li>` の右側の境界線で区切った枠の中に、コピーボタン、削除ボタンの順で並べる（`gap-0.5` 程度）。コピーは削除より使う頻度が高く、削除を一番端に置くほうが押し間違えたときの影響が小さいため、コピーを左にする。

- コピーボタンの名前は `` `${hex} をコピー` ``。削除ボタンの「#336699 を削除」と同じ形にそろえる
- HEX は保存されている小文字の `#rrggbb` をそのまま渡す（変換欄の HEX のコピーと同じ形式）

### D3. テスト

- `copy-button.test.tsx`: `variant="subtle"` のとき枠のクラス（`border`）を持たず、コピーと結果のアイコン切り替えが既定と同じに動く
- `favorite-colors.test.tsx`: 「#336699 をコピー」を押すとクリップボードに `#336699` が入り、「コピーしました」が読み上げられ、`onSelect` が呼ばれない。Tab で移動して Enter でコピーできる（既存の「キーボードだけで選択と削除ができる」の Tab の順番に、コピーボタンが加わるので、そのテストも更新する）
- `color-tool.test.tsx`: お気に入りに登録した色をコピーしても、変換の入力欄が変わらないことを確かめる（コンポーネントをまたぐふるまいのため）

## Risks / Trade-offs

- [項目ごとにボタンが1つ増え、Tab の移動回数が増える（最大 10 件で 10 回）] → 一覧の操作は今も各項目に2つのボタンがあり、3つになっても順番は項目ごとにまとまっている。許容する
- [項目の横幅が広がり、狭い画面で1行に並ぶ数が減る] → `flex-wrap` で折り返すので、はみ出しはしない。幅 390px のスクリーンショットで確かめる
- [`subtle` の状態の色の付け方を間違えると、成功時に緑にならない] → テストで成功時のアイコン（チェック）を確かめ、色はスクリーンショットで確かめる
