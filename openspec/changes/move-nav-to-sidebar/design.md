# Design

## Context

- 今の `app/layout.tsx` は、`body` の中に `Header`（アプリ名とアイコンのリンク）、`ToolNav`（横並びで折り返すツール一覧、`<Suspense>` で囲む）、各ページの `main`（`mx-auto max-w-5xl px-4 py-8`）を縦に並べている。
- 幅 1470px では、ヘッダー（約 57px）とツール一覧（2行で約 81px）で上部の約 140px を使う。
- 各ツールの欄の高さは、1470×800 で縦スクロールが出ないように固定の値にしている（例: Markdownプレビューは `h-118`、内容の下端 798px）。
- アプリは static export で配信し、依存パッケージは増やさない（AGENTS.md）。jsdom の `<dialog>` は `showModal()` / `close()` を実装していない。

## Goals / Non-Goals

**Goals:**

- 幅 1024px 以上では、上部の帯をなくして縦の高さをツールに回す
- ツールが増えても、ナビゲーションが折り返さずに縦に伸びるだけにする

**Non-Goals:**

- 欄の高さを画面の高さに合わせて伸び縮みさせること（今までどおり、1470×800 を目安に固定の値で決める）

## Decisions

### D1. 配置: 幅 1024px 以上は左にサイドバー、それ未満は上部のバー

`app/layout.tsx` の `body` を `lg` 以上で横並び（`lg:flex-row`）にする。

- **サイドバー（`components/sidebar.tsx` の `Sidebar`）**
  - `hidden lg:flex`、幅 `w-56`（224px）、`shrink-0`
  - `sticky top-0 h-dvh` で画面の高さに固定し、中身が長いときはサイドバーの中でスクロールする（`overflow-y-auto`）
  - 右の境界線（`border-r`）、上にアプリ名のリンク、その下にツール一覧
- **上部のバー（`components/mobile-header.tsx` の `MobileHeader`）**
  - `lg:hidden`。アプリ名のリンクとメニューボタンを横に並べる（高さ約 48px）
- **メイン**
  - 各ページの `main` は `flex-1 min-w-0` の領域の中で、今までどおり `mx-auto max-w-5xl` で中央に寄せる
  - 幅 1470px では、メインに使える幅は 1470 − 224 = 1246px で、1024px の内容が中央に来る
- 幅 1024px でも、サイドバーの右に `max-w-5xl`（1024px）の内容を置くと幅が足りない（800px）。`max-w-5xl` は「最大」なので、その場合は残りの幅いっぱいになる。各ツールの `lg:` の2列表示は 800px 幅で確認する。

### D2. ナビゲーションは縦並びの1つの部品を、サイドバーとメニューで使い回す

- `components/tool-nav.tsx` の `ToolNavList` を縦並び（`flex-col`）に変え、項目は幅いっぱいのブロックのリンクにする。現在地の強調（`aria-current="page"` と塗りつぶし）は今までどおり。
- サイドバーとメニューのどちらでも `<Suspense fallback={<ToolNavList items={navItems} />}><ToolNav items={navItems} /></Suspense>` を使う（`usePathname` の扱いは今までどおり）。
- アプリ名とアイコンのリンクは `components/header.tsx` の中身を `components/brand-link.tsx`（`BrandLink`）に移し、サイドバーと上部のバーで使い回す。`header.tsx` は削除する。

### D3. メニューは `<dialog>` の `showModal()` で開く

- `components/mobile-menu.tsx`（`MobileMenu`、Client Component）が、メニューボタンと `<dialog>` を持つ。
- `showModal()` で開くと、ブラウザが次を行う。依存パッケージを増やさずに、キーボードとスクリーンリーダーで使えるメニューになる。
  - フォーカスをダイアログの中に閉じ込める
  - ダイアログの外を操作できなくする（inert）
  - Esc キーで閉じる
  - 閉じたら、開く前にフォーカスがあった要素（メニューボタン）へフォーカスを戻す
- ボタンには `aria-expanded` と `aria-controls` を付ける。開いているかどうかは `<dialog>` の `close` イベントで state に反映する。
- ダイアログの中には、見出し「ツール」・閉じるボタン（×、`aria-label="メニューを閉じる"`）・ツール一覧を置く。
- ツールのリンクを押したら閉じる。`ToolNavList` に `onNavigate` を渡し、リンクの `onClick` で `close()` を呼ぶ。
- 見た目は画面の左に寄せたパネル（高さ `h-dvh`、幅 `w-72`、狭い画面ではみ出さないよう `max-w-full`）とし、`::backdrop` は Tailwind の `backdrop:` バリアントで半透明の黒にする。任意値（`max-w-[85vw]` など）は使わない。
- メニューを開いたまま画面を 1024px 以上に広げたときは、`matchMedia('(min-width: 1024px)')` の変化で閉じる（サイドバーと二重にならないように）。
- テスト: jsdom は `showModal()` / `close()` を実装していないので、テストの中で `HTMLDialogElement.prototype` に、`open` 属性の付け外しと `close` イベントの発火だけを行う代わりの関数を入れる。フォーカスの閉じ込めと Esc キーはブラウザの機能なので、開発サーバーで確かめる。

### D4. 空いた高さで各ツールの欄を広げる（1470×800 で実測して決める）

- 幅 1024px 以上では上部の約 140px が空く。ツールごとに、1470×800 で初期表示と spec の「通常の操作の後」の状態の内容の下端が 800px 以内に収まる範囲で、高さが制限されている欄を広げる。
- 対象と、変える値:
  - JSON整形/検証: 入力欄・出力欄の `rows={10}`
  - 文字数カウント: 入力欄の `rows={10}`
  - UUID/パスワード生成: 生成結果の行数の上限（今は `Math.min(Math.max(件数, 3), 10)` の 10）。名前付き定数にする
  - テキスト差分比較: 入力欄の `rows={8}`、比較結果の欄の `max-h-64`
  - チェックリスト: 各リストの一覧の `max-h-72`
  - Markdownプレビュー: 入力欄・プレビューの `h-118`
- 上の値は、`lg` 未満（縦に並べる表示）でも同じ値を使う。狭い画面では縦スクロールしてよいので、欄が大きくなっても問題はない（spec のとおり）。
- 具体的な値は、サイドバーの配置を入れた後に実測して決め、この design に記録する（実装のタスク）。

## Risks / Trade-offs

- [幅 1024〜1270px では、メインの幅が 1024px より狭くなり、2列表示の欄が狭くなる] → 2列表示は今までも幅 1024px のときに約 960px で表示していた。800px 幅でも横スクロールが出ないことを確認する。
- [固定の高さなので、800px より高い画面では余白が残る] → 今までの方針（1470×800 を目安に固定の値）を変えない。画面の高さに合わせて伸ばすのは対象外。
- [`<dialog>` の `backdrop:` や `showModal()` に対応しない古いブラウザ] → 対象のブラウザ（AGENTS.md・Next.js の対応ブラウザ）はすべて対応している。
- [メニューを閉じるときにリンクの遷移と `close()` が同時に起きる] → `close()` は同期で、遷移はその後に起きる。開発サーバーで、遷移とメニューが閉じることを確かめる。
