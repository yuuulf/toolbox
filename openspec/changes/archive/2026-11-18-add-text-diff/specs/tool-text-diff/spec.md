# Spec Delta

## Purpose

2つのテキストの違いを、行単位と、変更された行の中の文字単位で、ブラウザ内で比べて左右に並べて表示するツール。入力したテキストは保存しない。

## ADDED Requirements

### Requirement: 入力と同時に比較する
ツールは「変更前」と「変更後」の2つの入力欄を持ち、どちらかの内容が変わるたびに、ボタン操作なしで比較結果を更新しなければならない（SHALL）。

#### Scenario: 入力すると結果が更新される
- **WHEN** ユーザーが変更前に `a\nb`、変更後に `a\nc` を入力する
- **THEN** ボタンを押さなくても、`b` が削除され `c` が追加されたことを示す結果が表示される

### Requirement: 行単位で差分を示す
ツールは2つのテキストを改行で区切った行の並びとして比べ、両方に共通する行をできるだけ多く残したうえで、変更前にだけある行を削除、変更後にだけある行を追加として示さなければならない（SHALL）。末尾の改行の有無の違いも1行の違いとして示す。

#### Scenario: 行の追加と削除
- **WHEN** 変更前が `りんご\nみかん\nぶどう`、変更後が `りんご\nぶどう\nもも` である
- **THEN** `りんご` と `ぶどう` は共通の行、`みかん` は削除、`もも` は追加として表示される

#### Scenario: 末尾の改行だけが違う
- **WHEN** 変更前が `a`、変更後が `a\n` である
- **THEN** 変更後の末尾に空の行が1行追加されたと表示される

### Requirement: 変更された行の中で変わった文字を示す
削除された行と、同じ位置に追加された行は、変更された行の組として横に並べなければならない（SHALL）。組になった行では、行の中で変わった文字（変更前で消えた文字と、変更後で加わった文字）を、それ以外の文字と区別して示さなければならない。文字は見た目の1文字（書記素クラスタ）単位で比べる。組にならない行（削除または追加だけの行）は行全体を削除・追加として示す。

#### Scenario: 1文字だけ違う行
- **WHEN** 変更前が `価格は100円です`、変更後が `価格は120円です` である
- **THEN** 2つの行が横に並び、変更前の `0` のうち1文字が消えた文字、変更後の `2` が加わった文字として強調され、ほかの文字は強調されない

#### Scenario: 絵文字を含む行
- **WHEN** 変更前が `👨‍👩‍👧 あ`、変更後が `👨‍👩‍👦 あ` である
- **THEN** 絵文字が1文字として扱われ、変更前の `👨‍👩‍👧` と変更後の `👨‍👩‍👦` がそれぞれ1文字の変化として強調される

#### Scenario: 削除と追加の行数が違う
- **WHEN** 変更前が `x\n1\n2\ny`、変更後が `x\nA\ny` である
- **THEN** `1` と `A` が組として横に並び、`2` は組にならない削除の行として表示される

### Requirement: 結果を左右に並べて表示する
ツールは比較結果を、左に変更前、右に変更後を置き、共通の行と変更された行の組を同じ高さにそろえて表示しなければならない（SHALL）。片側にしかない行の反対側は空けておく。両側の各行に、元のテキストでの行番号を表示する。結果が長いときは、ページ全体ではなく結果の表示欄の中でスクロールできなければならない。

#### Scenario: 左右の対応
- **WHEN** 変更前が `a\nb`、変更後が `a\nB\nc` である
- **THEN** 1行目に `a`（左右とも行番号1）、2行目に左 `b`・右 `B`（行番号2）、3行目に左は空・右 `c`（行番号3）が並ぶ

### Requirement: 狭い画面では1列にまとめる
画面幅が 640px 未満のときは、ツールは結果を1列にまとめ、共通の行は1回だけ、変更された行は削除の行の後に追加の行を並べて表示しなければならない（SHALL）。ページ全体の横スクロールを発生させてはならない。

#### Scenario: スマートフォン幅での結果
- **WHEN** 画面幅 360px で、変更前 `a\nb`・変更後 `a\nc` を比べる
- **THEN** 結果は `a`、削除の `b`、追加の `c` の順に1列で表示され、横スクロールは発生しない

### Requirement: 追加と削除を色以外でも示す
ツールは追加・削除の行を、色に加えて行頭の記号（追加は `+`、削除は `-`）で示し、スクリーンリーダーでは「追加」「削除」と読み上げられるようにしなければならない（SHALL）。行の中で変わった文字は、色に加えて、消えた文字には取り消し線、加わった文字には下線を付けなければならない。

#### Scenario: 色が見分けられない場合
- **WHEN** 色を区別できないユーザーが比較結果を見る
- **THEN** 行頭の `+` / `-` と、文字の取り消し線・下線で、追加・削除と変わった文字が分かる

### Requirement: 結果がないときの表示
ツールは、両方の入力欄が空のときは「比較するテキストを入力してください。」を、2つのテキストが同じときは「差分はありません。」を表示し、比較結果の表は表示してはならない（SHALL）。これらの文言はスクリーンリーダーで読み上げられなければならない。

#### Scenario: 両方空
- **WHEN** ツールを開いた直後で、どちらの入力欄も空である
- **THEN** 「比較するテキストを入力してください。」が表示される

#### Scenario: 同じテキスト
- **WHEN** 変更前と変更後に同じ `a\nb` を入力する
- **THEN** 「差分はありません。」が表示される

### Requirement: 大きすぎる入力は比較しない
どちらかの入力が 5,000 行を超えるとき、ツールは比較を行わず、「比較できるのは 5,000 行までです。」を表示しなければならない（SHALL）。1行が 1,000 文字を超える変更された行の組では、文字単位の強調を行わず、行全体を削除・追加として示す。入力中に画面の操作が止まってはならない。

#### Scenario: 行数の上限を超える
- **WHEN** 変更前に 5,001 行のテキストを貼り付ける
- **THEN** 比較結果の代わりに「比較できるのは 5,000 行までです。」が表示される

### Requirement: 入力を保存・送信しない
ツールは入力したテキストと比較結果を保存してはならず（MUST NOT）、外部へ送信してはならない。ページを再読み込みすると、入力欄は空に戻る。

#### Scenario: 再読み込み
- **WHEN** 2つのテキストを入力した後でページを再読み込みする
- **THEN** 両方の入力欄は空で、「比較するテキストを入力してください。」が表示される
