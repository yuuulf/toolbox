# Design

## Context

- 計測値と動機は proposal.md を参照
- 共通の枠: ヘッダー（53px）とナビ（45px）。ツールページの `main` は `max-w-5xl`（1024px）、`px-4 py-8`。h1・説明・`mt-6` を合わせて、ツール本体は上から約 214px の位置から始まる。下の余白は 32px なので、ツール本体に使える高さは 1470×800 で約 550px
- 各ツールは縦一列（`flex flex-col`）で、`lg` 以上でも並びは変わらない
  - JSON整形: 入力欄（`rows={10}`）→ インデントとボタン → メッセージ → 出力欄（`rows={10}`）
  - UUID/パスワード生成: `UuidSection` → `PasswordSection`（`gap-10`）
  - カラーツール: カラー変換 → お気に入り → コントラスト比（`gap-8`）
- 配置は jsdom では測れない。これまでの画面確認と同じく、ヘッドレス Chrome（スクラッチパッドに置いた playwright-core、リポジトリ外）で `document.documentElement.scrollHeight` を測れる

## Goals / Non-Goals

**Goals:**

- `lg`（1024px）以上で2列にし、1470×800 で4ツールとも `scrollHeight <= 800` にする
- DOM の順序（＝読み上げ順・Tab の順）は変えず、`lg` 未満の見た目も変えない

**Non-Goals:**

- ヘッダー・ナビの変更（proposal の Out of scope）
- `max-w-5xl` の変更。2列でも1列あたり約 490px あり足りるため、ページ幅は変えない

## Decisions

### 1. 2列化は CSS Grid の `lg:` バリアントで行う

各ツールのルート要素に `lg:grid lg:grid-cols-2 lg:gap-x-8` などを足す。`lg` 未満では今の `flex flex-col` のまま。ブレークポイントを `lg` にするのは、`md`（768px）では1列あたり約 350px になり、JSON の入力欄やカラーツールの入力欄が窮屈になるため。

- 代替案: コンテナクエリ → ツールの幅はページ幅で決まるので、ビューポート基準の `lg` で足りる

### 2. ツールごとの配置

- **JSON整形/検証**: DOM の順序（入力 → 操作 → メッセージ → 出力）は保つ
  - グリッドの配置で、入力欄を左上、操作とメッセージを入力欄の下、出力欄を右の列（`lg:col-start-2 lg:row-start-1 lg:row-span-3`）に置く
  - Tab の順は「入力 → インデント → 整形 → 圧縮 → コピー → 出力」のままで、見た目も左から右に流れる
  - 出力欄の高さは入力欄に合わせる（`rows={10}` のまま）
- **UUID/パスワード生成**: ルートの `flex flex-col gap-10` を `lg:grid lg:grid-cols-2 lg:gap-x-8 lg:items-start` にし、2つのセクションを左右に並べる
- **カラー変換/コントラスト**: カラー変換とお気に入りを左の列の1つのラッパーにまとめ、コントラスト比を右の列に置く
  - DOM の順序（変換 → お気に入り → コントラスト）は今と同じ
  - 見積もり: 左の列は約 490px（お気に入り1行の場合）、右の列は約 380px
- **文字数カウント**: 変更しない

### 3. 余白の調整は計測してから

まず決定2だけを入れて計測し、800px を超えるツールが残ったときだけ、共通の余白を詰める。詰める順番は、`app/tools/[slug]/page.tsx` の `py-8` → `py-6`、説明の後の `mt-6` → `mt-4` の順。ツール内の要素の大きさ（文字サイズ・入力欄の行数）は変えない。

### 4. カラーツールの案内を専用の行から移す

空の `aria-live` の行も、上下の間隔（`gap-4`）ぶんの場所を取っていた。そのため、行そのものをなくす。

- **入力を促す案内**: 空入力のとき、点線のプレビュー枠の中央に表示する。枠は常に同じ高さなので、色を入れても高さが変わらない。変換欄の `aria-live` の行は削除する。案内はページを開いたときから見えている静的な表示なので、読み上げの対象（`aria-live`）にしなくてよい
- **件数**: `FavoriteColors` に見出しの行を持たせる（`ColorTool` から見出しを移す）。見出しの横に `<件数>/10` を常に表示する。`10/10` で上限だとわかるので、上限を知らせる文は出さない
  - 件数の見た目は `3/10`。読み上げ用には `sr-only` で「10件中3件」とする（`3/10` のままでは「3スラッシュ10」と読まれるため）
  - 読み上げ用の件数に `id` を付け、`aria-live="polite"` にする。星ボタンは上限で押せないとき、`aria-describedby` でこの id を参照し、「10件中10件」が押せない理由として伝わるようにする。id は `ColorTool` で `useId` を使って作り、`ColorConverter` と `FavoriteColors` の両方に渡す
  - 変換欄の上限の案内の行は削除する。`ColorConverter` には上限の文言を持たせない

### 5. UUID/パスワード生成の行をそろえる（CSS Grid の subgrid）

2列にすると、UUID は「個数＋ボタン」が1行、パスワードは「長さ」「文字種」「ボタン」が縦に3段で、入力欄・ボタン・結果欄の高さが左右でずれる。

- パスワードも「長さ」の入力欄の横に「パスワードを生成」を置き、UUID と同じ形の行にする。文字種とエラーはその下に置く。これで Tab の順は「長さ → 生成 → 文字種」になる。生成の前に文字種を変えたい場合も、Shift+Tab で戻れる
- `lg` 以上では、親を `grid-cols-2` の4行のグリッドにし、各セクションを `row-span-4` の `grid-rows-subgrid` にする。行は「見出し」「入力欄＋ボタン」「補足（UUID は個数のエラー、パスワードは文字種とエラー）」「結果欄」の4つで、左右で同じ行の高さを共有する。そのため、UUID 側は補足の行がパスワードの文字種の高さぶん空き、結果欄の位置が左右でそろう
- 各セクションの直接の子を、この4つにそろえる（`lg` 未満では今と同じ `flex flex-col`）

### 6. 確認方法

スクラッチパッドの計測スクリプトで、1470×800 の4ページを測る。初期表示と、spec の「通常の操作の後」の両方で `scrollHeight` を確かめ、スクリーンショットも目視する。あわせて、幅 360px で横スクロールがないこと（既存の要件）も確かめる。スクリプトはリポジトリに入れない（Playwright を依存に加えないため）。

## Risks / Trade-offs

- [カラーツールでお気に入りを 10 件登録すると、色の一覧が複数行に折り返し、左の列が伸びる] → 実装後の計測では、10 件（4行に折り返し）でも 1470×800 に収まった。お気に入りの見出しの横幅や色見本の大きさを変えるときは、改めて計測する
- [UUID を大量に生成したときや、長い JSON を貼ったとき] → 入力欄・出力欄の中でスクロールするので、ページは伸びない（`textarea` は固定行数のまま）
- [ブラウザの UI（タブ・アドレスバー）を含めて画面が 800px の場合は、表示領域がもっと小さい] → 目安は表示領域 1470×800 とし、proposal の Out of scope に書いたとおり、それより小さい画面は対象外
- [グリッドで見た目の順序と DOM の順序が少しずれる（JSON の出力欄が右上に来る）] → Tab の順は入力 → 操作 → 出力で自然なまま。見た目も左の列が入力、右の列が出力なので、混乱しにくい
