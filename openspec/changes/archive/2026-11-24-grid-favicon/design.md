# Design

## Context

- ファビコンは `public/favicon-light.png`・`public/favicon-dark.png`（256×256 の RGBA）で、`app/layout.tsx` の `metadata.icons` が `media` 付きで切り替え、`components/brand-link.tsx` が同じ2枚を `next/image` で import して `dark:` で切り替えている。どちらもファイル名で参照しているので、ファイルを置き換えるだけで両方に反映される。
- 新しい元画像の色・マークの範囲は proposal.md の What Changes のとおり。前回までの元画像と同じく、背景色とカードの色は2000×2000 の全体でほぼ3色だけで、縁のアンチエイリアスだけが中間色になっている（計画時に全ピクセルの色を数えて確かめた）。
- 前回まで（`2026-11-18-replace-favicon`、`2026-11-19-update-favicon`）と同じく、画像の加工には Python の標準ライブラリと macOS の `sips` を使う。この環境には ImageMagick も Pillow もない。

## Goals / Non-Goals

**Goals:**

- 新しいマークを、背景を透明にして、16〜32px のタブでもできるだけ大きく見える画像にする

**Non-Goals:**

- 加工スクリプトをリポジトリに入れること（加工は一度きりで、依存も増やしたくないため。前回と同じ）

## Decisions

### D1. 加工方法は前回と同じ（背景を透明化 → 余白 4% の正方形に切り詰め → 256px）

- **背景の透明化**: 各ピクセルを「背景色 B と前景色 F（カードの2色のうち近いほう）の混ざり」とみなして不透明度を求め、色は F にする。縁もなめらかに透け、カードの間の隙間は透明になる。
  - 「背景色を透明にする」だけの方式（color to alpha）は使わない。ライト用では #424242 のカードまで半透明になり、ダーク用では背景と同じ #424242 との混ざりを正しく扱えないため。
  - ダーク用は背景が #424242、カードが白と #4DB6AC なので、B と F の組み合わせだけが前回と同じで、スクリプトは前回のものをそのまま使える。
- **切り詰め**: マークの範囲（1598×1600）を中心に、長辺 + 上下左右 4% の正方形（約 1728px）にする。元画像の中に収まるので、外側を足す必要はない。
  - 元画像の余白（約 10%）をそのまま残す案は採らない。タブの 16px ではカード1枚が 6px 程度になり、余白の分だけ小さく見えるため。前回までと同じ 4% にそろえる。
- **サイズ**: 256×256。前回と同じ。

### D2. 参照するコードとテストは変えない

- ファイル名と大きさが同じなので、`metadata.icons`・`BrandLink`・`app/layout.test.ts`・`components/brand-link.test.tsx` はそのまま通る。画像の内容（形・色）を確かめる自動テストは追加しない。PNG を読むために依存を足すことになり、一度きりの差し替えに見合わないため。内容は加工時のスクリプトでの検査と、目での確認で確かめる。

## Risks / Trade-offs

- [`media` 付きの `<link rel="icon">` に対応しないブラウザ（Safari など）では、OS がダークでもライト用が使われることがある] → 前回と同じ。ライト用は濃いグレーのカードと緑のカードなので、暗いタブでも緑のカードと形で見分けられる。
- [16px では 2×2 のカードの隙間が 1px 程度になり、つながって見えることがある] → 余白を 4% に詰めてできるだけ大きくする。デザインの変更は対象外。
- [ブラウザがファビコンをキャッシュし、公開後もしばらく古いアイコンが出る] → ファイル名を変えないため起こりうる。再読み込みで直る。ファイル名を変えると参照するコードも変わるので、今回は採らない。
