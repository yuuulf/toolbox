# Spec Delta

## MODIFIED Requirements

### Requirement: 共通ヘッダーとツール間ナビゲーション
システムはすべてのページに、トップページへ戻るアプリ名のリンクと、登録済みツールへのナビゲーションを表示しなければならない（SHALL）。画面幅が 1024px 以上のときは、これらを画面の左のサイドバーに縦に並べ、常に表示する。1024px 未満のときは、画面の上部のバーにアプリ名のリンクとメニューボタンを置き、ナビゲーションはメニューボタンで開くメニューの中に表示する。現在表示中のツールはナビゲーション上で区別できなければならない。アプリ名の左には toolbox のアイコンを表示し、OS のライト/ダーク設定に合わせてファビコンと同じ2種類を切り替えなければならない。アイコンは飾りとして扱い、リンクの読み上げ名はアプリ名のままでなければならない。

#### Scenario: ツールページからトップへ戻る
- **WHEN** ユーザーがツールページでアプリ名「toolbox」をクリックする
- **THEN** `/` に遷移する

#### Scenario: 現在のツールが強調される
- **WHEN** ユーザーが `/tools/id-generator` を表示している
- **THEN** ナビゲーション上の「UUID/パスワード生成」が他の項目と視覚的に区別される

#### Scenario: アプリ名の隣のアイコン
- **WHEN** ユーザーがライトモードまたはダークモードでいずれかのページを開く
- **THEN** 「toolbox」の左に、そのモードのファビコンと同じアイコンが表示され、アイコンをクリックしてもトップページへ遷移する。スクリーンリーダーではリンクが「toolbox」と読み上げられ、アイコンは読み上げられない

#### Scenario: 広い画面ではサイドバー
- **WHEN** 画面幅 1470px でいずれかのページを開く
- **THEN** 画面の左にアプリ名とすべてのツールへのリンクが縦に並んで表示され、ページの上部にヘッダーやツール一覧の帯は表示されない。ツールが7つあってもリンクは1列に並ぶ

#### Scenario: 狭い画面ではメニュー
- **WHEN** 画面幅 360px でいずれかのページを開き、上部のバーのメニューボタンを押す
- **THEN** ページの上にすべてのツールへのリンクが重ねて表示される。メニューを開く前は、ツールへのリンクは表示されていない

#### Scenario: メニューを閉じる
- **WHEN** 狭い画面でメニューを開いた後、Esc キーを押す、閉じるボタンを押す、またはツールのリンクを選ぶ
- **THEN** メニューが閉じる。ツールのリンクを選んだときは、そのツールのページに遷移する

#### Scenario: メニューをキーボードで使う
- **WHEN** 狭い画面でキーボードだけを使い、メニューボタンを Enter キーで押す
- **THEN** メニューが開いてフォーカスがメニューの中に移り、Tab キーでツールのリンクを順に移動できる。メニューを閉じるとフォーカスはメニューボタンに戻る。メニューボタンは開いているかどうかをスクリーンリーダーに伝える

### Requirement: デスクトップ幅では各ツールを縦スクロールなしで使える
システムは表示領域が 1470×800 程度のデスクトップ画面で、各ツールページを初期表示したとき、ツールのすべての操作要素と結果の表示欄がページの縦スクロールなしで見えるようにしなければならない（SHALL）。ヘッダーとナビゲーションも含める。生成した値や入力が長くなった場合は、ページ全体を伸ばすのではなく、入力欄・出力欄の中でスクロールさせてよい。表示領域の高さが 800px より大きいときは、高さが制限されている入力欄・結果の表示欄を、ページの縦スクロールが発生しない範囲で表示領域の下端まで広げる。800px より低いときは、欄は 1470×800 のときの大きさを最低とし、ページの縦スクロールが発生してよい。表示領域が幅 1024px 未満の場合は、この要件の対象外とし、縦に並べた表示のままでよい。

#### Scenario: 1470×800 での初期表示
- **WHEN** 表示領域 1470×800 で、JSON整形/検証・文字数カウント・UUID/パスワード生成・カラー変換/コントラスト・チェックリスト・テキスト差分比較・Markdownプレビューの各ページを開く
- **THEN** どのページでもページ全体の高さが表示領域の高さ以内に収まり、縦スクロールが発生しない

#### Scenario: 通常の操作の後
- **WHEN** 表示領域 1470×800 で、JSON整形/検証で数行の JSON を整形する、UUID/パスワード生成で既定の設定のまま UUID とパスワードを生成する、カラー変換/コントラストで色を変換してお気に入りに1件登録する、チェックリストの4つのリストにそれぞれ10件の項目を追加する、テキスト差分比較で 100 行ずつのテキストを比べる、Markdownプレビューで 100 行の Markdown と Mermaid の図を表示する
- **THEN** 操作の後もページの縦スクロールが発生しない（項目が多いリスト、長い比較結果、長いプレビューは、それぞれの表示欄の中でスクロールしてよい）

#### Scenario: 高い画面では欄を広げる
- **WHEN** 表示領域 1470×1100 で、JSON整形/検証・Markdownプレビューを開く、またはテキスト差分比較で 100 行ずつのテキストを比べる、チェックリストの4つのリストにそれぞれ30件の項目を追加する
- **THEN** 入力欄・出力欄・プレビュー・比較結果・各リストが 1470×800 のときより縦に大きく表示され、ページの縦スクロールは発生しない

#### Scenario: 低い画面では最低の大きさを保つ
- **WHEN** 表示領域 1470×700 で、各ツールページを開く
- **THEN** 高さが制限されている欄は 1470×800 のときと同じ大きさで表示され、ページを縦にスクロールしてすべての操作要素を使える

#### Scenario: 狭い画面では縦に並べる
- **WHEN** 画面幅 360px で各ツールページを表示する
- **THEN** 項目は縦一列に並び、横スクロールは発生しない（縦スクロールは発生してよい）
