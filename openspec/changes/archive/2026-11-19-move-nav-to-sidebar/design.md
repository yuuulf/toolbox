# Design

## Context

- 今の `app/layout.tsx` は、`body` の中に `Header`（アプリ名とアイコンのリンク）、`ToolNav`（横並びで折り返すツール一覧、`<Suspense>` で囲む）、各ページの `main`（`mx-auto max-w-5xl px-4 py-8`）を縦に並べている。
- 幅 1470px では、ヘッダー（約 57px）とツール一覧（2行で約 81px）で上部の約 140px を使う。
- 各ツールの欄の高さは、1470×800 で縦スクロールが出ないように固定の値にしている（例: Markdownプレビューは `h-118`、内容の下端 798px）。
- アプリは static export で配信し、依存パッケージは増やさない（AGENTS.md）。jsdom の `<dialog>` は `showModal()` / `close()` を実装していない。

## Goals / Non-Goals

**Goals:**

- 幅 1024px 以上では、上部の帯をなくして縦の高さをツールに回す
- ツールが増えても、ナビゲーションが折り返さずに縦に伸びるだけにする
- 幅 1024px 以上では、高さが制限されている欄を画面の高さに合わせて広げる。D4 の大きさを最低にする（実装後の確認で追加した要望）

**Non-Goals:**

- 画面の高さを JavaScript で測ること、`calc(100dvh - …)` のような任意値で高さを書くこと（CSS の flex だけで広げる）
- 1024px 未満（縦に並べる表示）で欄を画面の高さに合わせること

## Decisions

### D1. 配置: 幅 1024px 以上は左にサイドバー、それ未満は上部のバー

`app/layout.tsx` の `body` を `lg` 以上で横並び（`lg:flex-row`）にする。

- **サイドバー（`components/sidebar.tsx` の `Sidebar`）**
  - `hidden lg:flex`、幅 `w-56`（224px）、`shrink-0`
  - `sticky top-0 h-dvh` で画面の高さに固定し、中身が長いときはサイドバーの中でスクロールする（`overflow-y-auto`）
  - 右の境界線（`border-r`）、上にアプリ名のリンク、その下にツール一覧
- **上部のバー（`components/mobile-header.tsx` の `MobileHeader`）**
  - `lg:hidden`。アプリ名のリンクとメニューボタンを横に並べる（高さ約 48px）
- **メイン**
  - 各ページの `main` は `flex-1 min-w-0` の領域の中で、今までどおり `mx-auto max-w-5xl` で中央に寄せる
  - 幅 1470px では、メインに使える幅は 1470 − 224 = 1246px で、1024px の内容が中央に来る
- 幅 1024px でも、サイドバーの右に `max-w-5xl`（1024px）の内容を置くと幅が足りない（800px）。`max-w-5xl` は「最大」なので、その場合は残りの幅いっぱいになる。各ツールの `lg:` の2列表示は 800px 幅で確認する。

### D2. ナビゲーションは縦並びの1つの部品を、サイドバーとメニューで使い回す

- `components/tool-nav.tsx` の `ToolNavList` を縦並び（`flex-col`）に変え、項目は幅いっぱいのブロックのリンクにする。現在地の強調（`aria-current="page"` と塗りつぶし）は今までどおり。
- サイドバーとメニューのどちらでも `<Suspense fallback={<ToolNavList items={navItems} />}><ToolNav items={navItems} /></Suspense>` を使う（`usePathname` の扱いは今までどおり）。
- アプリ名とアイコンのリンクは `components/header.tsx` の中身を `components/brand-link.tsx`（`BrandLink`）に移し、サイドバーと上部のバーで使い回す。`header.tsx` は削除する。

### D2a. 現在地の判定で末尾の `/` を無視する（実装中に見つけた不具合の修正）

`trailingSlash: true`（toolbox-deployment）にしてから、`usePathname()` は `/tools/<slug>/` を返すようになり、`/tools/<slug>` と比べていた現在地の強調が効かなくなっていた（公開版の HTML にも `aria-current="page"` がない）。ナビゲーションを作り直すこの change で、末尾の `/` の有無を同じとみなして比べるように直す。

### D3. メニューは `<dialog>` の `showModal()` で開く

- `components/mobile-menu.tsx`（`MobileMenu`、Client Component）が、メニューボタンと `<dialog>` を持つ。
- `showModal()` で開くと、ブラウザが次を行う。依存パッケージを増やさずに、キーボードとスクリーンリーダーで使えるメニューになる。
  - フォーカスをダイアログの中に閉じ込める
  - ダイアログの外を操作できなくする（inert）
  - Esc キーで閉じる
  - 閉じたら、開く前にフォーカスがあった要素（メニューボタン）へフォーカスを戻す
- ボタンには `aria-expanded` と `aria-controls` を付ける。開いているかどうかは `<dialog>` の `close` イベントで state に反映する。
- ダイアログの中には、見出し「ツール」・閉じるボタン（×、`aria-label="メニューを閉じる"`）・ツール一覧を置く。
- ツールのリンクを押したら閉じる。`ToolNavList` に `onNavigate` を渡し、リンクの `onClick` で `close()` を呼ぶ。
- 見た目は画面の左に寄せたパネル（高さ `h-dvh`、幅 `w-72`、狭い画面ではみ出さないよう `max-w-full`）とし、`::backdrop` は Tailwind の `backdrop:` バリアントで半透明の黒にする。任意値（`max-w-[85vw]` など）は使わない。
- メニューを開いたまま画面を 1024px 以上に広げたときは、`matchMedia('(min-width: 1024px)')` の変化で閉じる（サイドバーと二重にならないように）。
- `showModal()` のダイアログでは、最後のリンクから Tab を押すとフォーカスはブラウザ自体の UI（アドレスバーなど）へ移り、ページのダイアログの外の要素には移らない（ブラウザの標準の動作）。
- テスト: jsdom は `showModal()` / `close()` を実装していないので、テストの中で `HTMLDialogElement.prototype` に、`open` 属性の付け外しと `close` イベントの発火だけを行う代わりの関数を入れる。フォーカスの閉じ込めと Esc キーはブラウザの機能なので、開発サーバーで確かめる。

### D4. 空いた高さで各ツールの欄を広げる（1470×800 で実測して決める）

- 幅 1024px 以上では上部の約 140px が空く。ツールごとに、1470×800 で初期表示と spec の「通常の操作の後」の状態の内容の下端が 800px 以内に収まる範囲で、高さが制限されている欄を広げる。
- 対象と、変える値:
  - JSON整形/検証: 入力欄・出力欄の `rows={10}`
  - 文字数カウント: 入力欄の `rows={10}`
  - UUID/パスワード生成: 生成結果の行数の上限（今は `Math.min(Math.max(件数, 3), 10)` の 10）。名前付き定数にする
  - テキスト差分比較: 入力欄の `rows={8}`、比較結果の欄の `max-h-64`
  - チェックリスト: 各リストの一覧の `max-h-72`
  - Markdownプレビュー: 入力欄・プレビューの `h-118`
- 上の値は、`lg` 未満（縦に並べる表示）でも同じ値を使う。狭い画面では縦スクロールしてよいので、欄が大きくなっても問題はない（spec のとおり）。
- 具体的な値は、サイドバーの配置を入れた後に実測して決めた。1470×800 で、各ツールの最も高くなる状態の内容の下端（`main` の下端）が 790px 前後に収まるようにした。

  | ツール | 欄 | 変更前 → 変更後 | 測った状態 | 下端（変更前 → 変更後の見込み） |
  | --- | --- | --- | --- | --- |
  | JSON整形/検証 | 入力欄・出力欄 | `rows={10}` → `rows={24}` | 初期表示・整形後 | 491px → 771px |
  | 文字数カウント | 入力欄 | `rows={10}` → `rows={24}` | 初期表示 | 484px → 764px |
  | UUID/パスワード生成 | 生成結果の行数の上限 | 10 → 20（定数 `UUID_ROWS_MAX`） | UUID 100件を生成 | 574px → 774px |
  | テキスト差分比較 | 入力欄 / 比較結果 | `rows={8}` → `rows={10}` / `max-h-64` → `max-h-88` | 100行ずつ比較 | 650px → 786px |
  | チェックリスト | 各リストの一覧 | `max-h-72` → `max-h-112` | 4つのリストに30件ずつ | 624px → 784px |
  | Markdownプレビュー | 入力欄・プレビュー | `h-118` → `h-150` | 100行と図 | 660px → 788px |

  - カラー変換/コントラストは変えない（初期表示・登録後とも 602px）

### D5. 画面の高さに合わせて広げる（幅 1024px 以上、CSS の flex だけで）

**ページの外枠**
- ツールのページの `main` を `lg:flex lg:flex-col lg:min-h-dvh` にし、ツールの領域（`app/tools/[slug]/page.tsx` の `<div className="mt-6">`）を `lg:flex lg:flex-1 lg:flex-col` にする。
- これで、ツールの領域は「画面の高さ − 見出しと説明と余白」以上の高さになる。各ツールのいちばん外の要素を `lg:flex-1` にして、その高さを使う。
- `min-h-dvh`（高さの下限）なので、中身が画面より高いときは `main` が伸び、ページが縦にスクロールする。これが「低い画面では最低の大きさを保ち、ページをスクロールしてよい」の動きになる。

**欄の広げ方は2種類**
- **埋める型（入力欄・出力欄・プレビュー）**: 欄を `lg:flex-1` にして残りの高さを埋める。D4 の `rows` や `h-*` が伸びる前の大きさ（flex-basis）になり、画面が低くても縮まないので、そのまま最低の大きさになる。
  - JSON整形/検証:
    - 今の `lg:grid`（入力・操作・結果の文を左、出力を右に3行ぶち抜き）を、左の列（入力・操作・結果の文）と右の列（出力）の2つの縦並びの列に組み直す
    - DOM の順序（入力 → 操作 → 結果の文 → 出力）と Tab の順は変わらない
    - 入力欄と出力欄を `lg:flex-1` にする
  - 文字数カウント: 入力欄（と、それを囲むラベル付きの枠）を `lg:flex-1` にする。下の集計は今の位置のまま、画面の下端に寄る
  - Markdownプレビュー:
    - 入力欄とプレビューを `lg:flex-1` にして、各欄の枠を広げる
    - プレビューは中身に合わせて伸びる箱なので、中身に合わせる型と同じく、各欄の枠（見出しの行と欄）に `lg:contain-size` と最低の高さ `lg:min-h-160`（640px = 見出しの行 36px + 間隔 4px + 今の `h-150` の 600px）を付ける
    - 欄そのものは `lg:h-auto lg:min-h-0 lg:flex-1`。実装中、これがないと 100 行の Markdown でページが 2968px まで伸びた
  - UUID/パスワード生成:
    - 生成結果の欄（`rows` は件数に合わせて 3〜20）を `lg:flex-1` にする
    - 件数が少なくても、広い画面では欄が下端まで広がる（JSON の出力欄と同じ見た目になる）
    - パスワードの欄は1行の入力なので広げない
- **中身に合わせる型（チェックリストの各リスト、テキスト差分比較の比較結果）**: 中身が少ないうちは中身の高さのまま、多いときは残りの高さまで伸び、その先は欄の中でスクロールする。
  - 欄を囲む縦並びの枠を `lg:flex-1` にし、欄そのものは `lg:min-h-0 lg:shrink`（伸ばさず、足りなければ縮む）にする。`max-h-*` は 1024px 未満だけに効くよう `lg:max-h-none` で外す。
  - 最低の大きさは、枠のほうに `lg:min-h-*` を付けて保つ。欄に付けると、中身が少ないときにも欄が大きくなり、下の追加の入力欄が離れてしまうため。
    - テキスト差分比較: 「比較結果」の見出しと欄を囲む枠に、見出しの行 + 今の `max-h-88` の高さを最低として付ける
    - チェックリスト:
      - 4つのリストのグリッドを `lg:flex-1` にする。各リスト（`section`）は、見出し・期間の入力・一覧・追加の入力欄を縦に並べ、一覧だけを `lg:min-h-0 lg:shrink` にする
      - グリッドには、30件ずつ入れたときの1列の高さ（今の `max-h-112` で測った値）を `lg:min-h-*` として付ける
      - `lg` で2列×2段になる幅（1024〜1279px）では、段ごとに高さが分かれる
- 枠の `lg:min-h-*` の値（実測で決めた）:
  - テキスト差分比較の比較結果の枠: `lg:min-h-95`（380px = 見出しの行 20px + 間隔 8px + `max-h-88` の 352px）
  - チェックリストの各リスト（`section`）: `lg:min-h-159`（636px = 30件のときのリストの1列の高さ）。グリッドではなく各リストに付けると、`lg`（2列×2段）と `xl`（4列）で同じ値で済む

**実装で分かったことと、それに合わせた作り（中身に合わせる型）**
- flex や grid の子は、既定の最低の高さ（`min-height: auto`）が中身の高さになる。そのため、一覧や比較結果を囲む枠が中身に合わせて伸びてしまい、欄が残りの高さで止まらなかった（30件のリストが 836px、100行の比較結果が 2002px になった）。
- `main` を `h-dvh`（高さを固定）にすると止まったが、画面が低いときに中身が `main` からはみ出す。下の余白がなくなり、サイドバーの境界線も途中で切れた。
- そこで、中身に合わせる型の枠（各リストの `section`、比較結果の枠）に `lg:contain-size` を付ける。`contain: size` を付けた要素は、親が最低の高さを求めるときに中身の高さを使わず、付けた `lg:min-h-*` だけで決まる。これにより:
  - `main` は `lg:min-h-dvh` のままでよい（画面が低いときは `main` ごと伸び、余白も保たれる）
  - 枠の高さは「残りの高さ」と `lg:min-h-*` の大きいほうになり、中の欄は中身の高さのまま、その枠の高さで止まる
- あわせて、ツールの領域と、中身に合わせる型の欄を含むツールのいちばん外の要素に `lg:min-h-0` を付ける（中身の高さで伸びないように）。
- `contain: size` は横方向の大きさの計算にも効くが、どちらの枠も幅はグリッドの列や親の幅いっぱいで決まるので、見た目は変わらない。

**実測の結果（1470px 幅、欄の高さ）**

| 欄 | 700px | 800px | 1100px |
| --- | --- | --- | --- |
| JSON整形/検証の入力欄 / 出力欄（D6 の配置の後） | 512 / 512 | 612 / 612 | 912 / 912 |
| 文字数カウントの入力欄 | 498（スクロールあり） | 534 | 834 |
| UUID の生成結果（100件 / 1件、D6 の後） | 418 / 38（スクロールあり） | 444 / 38 | 744 / 38 |
| テキスト差分比較の比較結果（100行） | 352（スクロールあり） | 366 | 666 |
| チェックリストの一覧（30件ずつ、列ごと） | 448〜492（スクロールあり） | 464〜508 | 764〜808 |
| Markdownプレビューの入力欄・プレビュー | 600（スクロールあり） | 612 | 912 |

- 中身が少ない一覧（3件）は 80px のままで、追加の入力欄は一覧の 12px 下にある。
- 画面が低い（700px）ときは、`main` の下端が中身の下端 + 下の余白（32px）になる。

### D6. 実装後の確認で変えた配置（ユーザーの指摘）

- **UUID の生成結果は中身に合わせる型にする**
  - 今までは件数が少なくても欄が画面の下端まで広がっていた。初期表示と1件のときは1行の欄にする
  - `rows` は件数（最低1行、上限なし）にし、欄を囲む枠に `lg:contain-size` と最低の高さ（見出しの行 + 20行分）を付けて、中身の高さのまま残りの高さまで伸ばす（D5 の中身に合わせる型と同じ）
  - 1024px 未満では、20行分を超えたら欄の中でスクロールするよう `max-h-*` を付ける（今の上限 20行と同じ大きさ）
- **JSON整形/検証の操作は「入力」の見出しの行に置く**
  - インデントの選択・「整形」・「圧縮」を、入力欄の上の見出しの行の右に移す（Markdownプレビューと同じ置き方）。その分、入力欄が縦に広がる
  - DOM の順序は「見出しの行（ラベル・操作）→ 入力欄 → 結果の文 → 出力」になり、Tab の順も「操作 → 入力欄」に変わる（Markdownプレビューと同じ）

## Risks / Trade-offs

- [幅 1024〜1270px では、メインの幅が 1024px より狭くなり、2列表示の欄が狭くなる] → 2列表示は今までも幅 1024px のときに約 960px で表示していた。800px 幅でも横スクロールが出ないことを確認する。
- [ツールごとに外枠から欄までの縦並びをつなぐ必要があり、どこか1か所でも `flex-1` が抜けると広がらない] → 1470×1100 と 1470×700 で、欄の大きさとページのスクロールを実測で確かめる。
- [`<dialog>` の `backdrop:` や `showModal()` に対応しない古いブラウザ] → 対象のブラウザ（AGENTS.md・Next.js の対応ブラウザ）はすべて対応している。
- [メニューを閉じるときにリンクの遷移と `close()` が同時に起きる] → `close()` は同期で、遷移はその後に起きる。開発サーバーで、遷移とメニューが閉じることを確かめる。
